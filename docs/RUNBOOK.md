# RUNBOOK — poket_game

`poket_game` — статический фронтенд на GitHub Pages. У проекта нет серверного процесса, базы данных, контейнеров и фоновых задач.

## Локальный запуск

Требуется Node.js 22.

```bash
npm ci
npm run dev
```

Проверка перед публикацией:

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

Собранная статика лежит в `dist/`.

## Деплой

Пуш в `main` запускает `.github/workflows/deploy.yml`. Workflow устанавливает зависимости через `npm ci`, выполняет typecheck, тесты и сборку, затем публикует `dist/` в GitHub Pages.

Ручной запуск доступен через `workflow_dispatch`. Успешный деплой подтверждается зелёным workflow и ответом HTTP 200 от `https://kartuznik.github.io/poket_game/`.

## Мониторинг

Prometheus, Grafana, `/health` и серверных логов нет. Сигналы состояния:

- результат workflow `Deploy to GitHub Pages`;
- доступность опубликованной страницы;
- браузерная консоль при воспроизведении клиентской ошибки.

## Данные, backup и restore

Данные визита хранятся только в `localStorage` браузера пользователя. Серверного хранилища и серверного backup нет.

Пользователь может сохранить результат через CSV, HTML-отчёт или копирование текста. Восстановление серверного снимка невозможно: продукт не получает пользовательские данные.

## Rollback и инциденты

При неуспешной публикации:

1. Открыть упавший workflow и определить первый неуспешный шаг.
2. Воспроизвести локально `npm ci`, `npm run typecheck`, `npm test` и `npm run build`.
3. Исправить причину отдельным коммитом или вернуть документированным git-коммитом последнюю неисправную правку.
4. Дождаться зелёного workflow и проверить живую страницу.

Историю git не переписывать. Опубликованная версия откатывается новым коммитом, который возвращает нужное состояние.

## Секреты и ключи

Приложению не нужны `.env`, API-ключи или серверные учётные данные. Ротация ключей для приложения не применяется. Настройки GitHub Pages и права workflow меняет только владелец репозитория.
